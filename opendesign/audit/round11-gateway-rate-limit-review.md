# 第十一轮：CloudBase HTTP 网关共享限频复核

日期：2026-08-29

## BACK-012：生产网关路由未配置共享限频

- 唯一编号：`BACK-012`
- 严重程度：严重
- 影响范围：ASR、语义解析、辅助问答等高成本接口在云托管扩容到多个实例后，无法由网关提供统一的全局 QPS 上限；单实例后端限流不能替代多实例共享控制。
- 复现步骤或证据：
  1. 通过已登录 CloudBase 新版控制台进入“HTTP 网关”。
  2. 找到默认域名的 `/` 路由，资源对象为 `watchdog-api-prod`，路由状态为“已开启”。
  3. 打开该路由的“限频设置”只读对话框；“资源维度限频（标准版）”和“客户端维度限频（企业版）”均未勾选，限频值均为禁用状态；列表列“限频设置”显示“未设置”。
- 根本原因：CloudBase 网关当前没有配置共享限频；后端 `backend/src/rate-limiter.js` 的固定容量限流器只覆盖单个进程，无法形成跨实例全局上限。
- 涉及文件/平台：CloudBase HTTP 网关 `/` 路由、`watchdog-api-prod`、`backend/src/rate-limiter.js`、`backend/src/server.js`。
- 修改方案：由网关提供资源维度共享限频；本轮采用平台允许的保守总量 100 QPS，客户端维度因当前套餐能力未启用。保留后端进程级 429 止损，使用隔离环境的突发流量、429 比例、实例数和上游耗时做多实例压测校准，不凭经验扩大配额。
- 修复状态：网关资源维度限频已配置；客户端维度限频和多实例压测仍为外部观察项。
- 验证结果：CloudBase API `DescribeHTTPServiceRoute` 回读目标路由 `QPSPolicy.QPSTotal=100`，更新时间已更新；配置后健康接口连续 3 次返回 HTTP 200；后端既有 161/161 回归和固定容量限流器证据保持有效。

## 与 DEPLOY-002 的关系

服务已通过部署 030 恢复并连续验证可用；资源维度总限频已配置为 100 QPS。后续只在隔离环境完成多实例压测和阈值校准，不在生产制造压力。
