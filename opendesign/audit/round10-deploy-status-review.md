# 第十轮：CloudBase 云托管服务状态复核

日期：2026-08-29

## DEPLOY-002：生产托管服务暂停，公网入口不可用

- 唯一编号：`DEPLOY-002`
- 严重程度：阻断（原登记为严重；当前实测已影响全部公网 API）
- 影响范围：线上 API 可达性、App 认证、警情同步、语音识别、后台值守和后续生产验收。
- 复现步骤或证据：
  1. 通过已登录 CloudBase 控制台进入环境 `watchdog-prod-d6gch930m378d9a16` 的“云函数 / 托管 → 服务管理”。
  2. 服务列表显示 `watchdog-api-prod` 运行状态为“已暂停”。
  3. 服务详情显示最新部署 029 状态为“正常”、流量 100%，但实例数量为 0；服务详情的运行状态仍为“已暂停”。
  4. 只读 HTTP 检查结果：应用网关根路径、应用网关 `/api/health` 和服务默认域名 `/api/health` 均返回 HTTP 503；检查命令未保存响应正文。
- 根本原因：平台服务状态、部署版本状态和公网转发结果当前一致地表明没有可用运行实例，但此前部署记录曾报告健康检查通过；现有证据不足以判断暂停触发原因（平台状态、实例回收、配额或服务事件）。
- 涉及文件/平台：CloudBase `watchdog-api-prod`、HTTP 网关、`deploy/deploy.sh`；本轮没有修改代码或生产配置。
- 修改方案：由运维在控制台核对暂停原因、服务事件、实例日志和当前部署版本；确认恢复方式后再执行一次明确的启用/恢复操作。恢复后连续复核网关与默认域名健康接口、模型清单、401 鉴权边界及 App 关键链路，并记录恢复时间和实例数。恢复前不执行 PostgreSQL 迁移、OTA 发布或新的生产发布。
- 修复状态：外部阻塞已重新确认；本轮未点击启用、重启、更新、回退、删除、升级套餐或重新部署。
- 验证结果：CloudBase 新版控制台只读核查完成；本机三条 HTTPS 只读检查均返回 503；未读取、保存或写入任何密钥及业务数据。

## 安全边界

服务详情页会显示部分运行时环境变量。该现象仍归入 `SEC-018`；本轮只确认其存在，不记录具体值，不截图、不复制，也不执行密钥轮换。密钥轮换必须在恢复方案、影响评估和新值关键链路验证完成后进行。

## 下一步

1. 恢复前保持 `DEPLOY-002` 为阻断项，不把部署版本“正常”误判为服务可用。
2. 恢复操作完成后必须连续通过健康检查；主 Agent 已完成恢复并保留恢复时间、部署号和检查结果。
