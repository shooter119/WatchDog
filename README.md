# 火场智控

一款由消防员开发、给消防员用的 App，火场安全管控的消防救援智能体。

## 为什么会有这个 App

火场里，安全员是最要紧也最紧张的岗位。进了多少人、进去多久了、谁的气瓶快空了——每一个数字都人命关天。

但现场往往是这样：防护服、手套、对讲机的嘈杂声，烟雾里看不清纸笔，指挥员一句「报一下里面几个人」，靠的是一张被水打湿的名单和一个记在心里的时间。气瓶剩余时间要心算，人多了一乱就错。我们太清楚那种手忙脚乱的感觉了。

安全员真的没时间翻记录本。所以这个 App 从头到尾只坚持一件事：**让你张嘴说话，剩下的交给它**。

## 它是怎么用的

安全员站在入口，队员进场时报一句「张三，24」：

- App 自动听清人名和压力值，算好这瓶气还能用多久
- 谁进来、谁出去、还剩多少分钟，看板上实时滚动
- 快没气了，App 会先说话提醒，再响警报
- 退场时一句「张三退场」，记录自动归档

全程不用敲一个字，戴着战术手套也按得动。底部就五个入口：**日志、看板、语音、辅助、设置**。中间那个橙色的麦克风，就是安全员最快的那只手——按住说话，文字会边说边出现，松手后快速定稿；单次录音最长 60 秒，接近上限会提示，时间到自动结束并继续处理已录内容。云端连接异常时保留录音并自动切换本机识别。

多台设备加入同一场警情档案后，指挥员和多个安全员看到的是同一块看板，数据实时同步；处置结束后档案自动归档，名称和完整火场时间线都可在设置中复盘。

## 它能帮你什么

- **语音录入**：进场、退场、压力值，一句话搞定；支持边说边返回文字，松手后再进行一次业务解析；多人进场一次报完一次确认，每个人的气瓶容量还能单独改；单次录音最长 60 秒，最后 10 秒提示，到点自动处理已录内容，云端失败自动回退本机 ASR
- **自动计算**：气瓶容量、压力、消耗率交给我们算，剩余 10 分钟提醒、5 分钟报警
- **实时看板**：在场谁、进去多久、还剩多久，一目了然；到点自动播报、响警报，锁屏也推通知
- **火场日志**：进场自动记录为「张三进入救援现场，空气呼吸器压力24兆帕」，撤离自动记录为「张三撤离救援现场」；其他现场信息也可语音记入，按实战环节分类（部署/搜救/出水/撤离/异常），回头好复盘
- **辅助问答**：火场智囊「水元素」——浓烟里拿不准主意，按住说话问一句，语音转写仅作为辅助页与 AI 交流的文字，不会发布到火场日志；默认联网检索，遇到陌生危险化学品等问题可查找最新资料，再按「结论、立即行动、注意事项」简洁给出建议。收到整段警情简报时会主动研判风险、处置要点和待核实信息，不必再追问“想了解什么”；对话历史只保存在本机，不关联警情、不参与多人协同
- **单位语音词库**：完成单位认证后自动加载本单位预置姓名、专业词汇和成员新增词条；所有已认证用户都可直接补充词条，词库同时注入云端与本机识别；退出单位后本机自动清空该单位词库
- **数据统计**：每人的进出场次数、时长一清二楚，训练复盘心里有数
- **断网可用**：语音识别与语义解析都能在本机运行（本地 ASR 主模型约 75MB，另有可选的 9.8MB 降噪模型）；模型下载和缓存启用前会按部署清单校验大小与 SHA-256，低存储时不会自动删除当前模型或现场数据，可清理空间后重试或继续联网识别，火场没信号照样录
- **版本更新**：正式 APK 通过 GitHub Release 发布，App 可检查公开 Release、校验 SHA-256 后交由系统安装器更新
- **用户认证与警情档案**：首次启动先在浮层填写单位名称、姓名和单位验证码完成认证，认证后在同一浮层选择正在处置的警情或一键新建；测试环境可预置“龙游县消防救援大队”（验证码 0570），生产环境需显式配置单位种子，不会改写已有警情的单位归属；未完成认证/警情选择前底部导航与语音入口会被锁定；警情名称、参战消防站、车辆和人员数量可协同维护
- **自动归档**：连续 12 小时没有现场业务活动自动归档；归档页按时间查看档案、参战力量快照和晚到早的完整事件时间线
- **离线补传**：已加入警情后，进退场、压力复核和随手记会持久化暂存，恢复网络后按发生顺序幂等补传
- **后台诊断**：App 捕获 Flutter/Dart 未处理异常后写入本地滚动日志，联网且已加入警情时自动脱敏补传，便于分析红屏和插件异常，不增加操作界面
- **火场友好**：屏幕常亮、后台保活、按键式录音，戴着手套、满场嘈杂也能用

## 适用现场

室内烟火特性训练、楼层火灾进攻、化工装置处置……凡是需要安全员盯着气瓶和人员的现场，都适用。训练场上练顺手了，真打火场才不慌。

## 关于这个项目

由一线消防员在工作之余开发，后端与 App 全部开源。联网时语音识别通过后端代理豆包实时流式 ASR，语义理解是 DeepSeek；云端失败或断网时自动切到本机 sherpa-onnx 识别和规则解析，两套兜底都备着。项目进展见 [STATUS.md](STATUS.md)。

我们不是软件公司，就是一群想让安全员轻松一点的战友。如果你的队伍也用得上，欢迎提需求、提 bug——每一个意见，都可能救下一个兄弟。

## 后端部署

后端使用标准 PostgreSQL 17，业务写入、永久审计事件和实时 Outbox 在同一事务中提交，通过 PostgreSQL `LISTEN/NOTIFY` 唤醒多实例，再由 WebSocket 推送给同单位在线 App。App 首次认证后获取单位词库和警情快照，在线期间只保持一条业务 WebSocket，并每 30 秒轻量校准；断网操作进入本地队列，恢复后幂等补传。模型由后端 `/models/` 目录分发，部署平台不作限定。

本地开发：先启动 PostgreSQL 17 并创建 `watchdog_dev` / `watchdog_test`，在 `backend/` 执行 `npm run db:migrate` 和 `npm test`；再将 App 的服务器地址配置为 `http://10.0.2.2:3000`（Android 模拟器）或通过 `--dart-define=WATCHDOG_API_BASE_URL=...` 指定其他后端。
