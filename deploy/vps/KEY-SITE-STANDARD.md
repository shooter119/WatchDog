# 重点单位基本情况标准

标准定义来自单位基本情况表的栏目结构，适用于化工等单位；未涉及的类别留空，不为每家单位开发专用页面。真实样表、联系方式和厂区资料保留在私有环境，以下定义不包含样表实值。

## 页面与记录

| 页面 | 标准记录 | 填写粒度与内容 |
|---|---|---|
| 作战信息卡 | 单位基本情况 | 原文名称地址和值班电话、总人数及白夜班人数、建筑结构、占地及建筑面积、性质与功能分区 |
| 作战信息卡 | 毗邻与道路 | 东南西北毗邻企业、不可停靠道路及通行条件 |
| 作战信息卡 | 生产装置 | 每套装置一条，记录危化品、危险工艺、固定消防设施、耐火等级、层数及高度 |
| 作战信息卡 | 消防设施及水源 | 控制室及泵房、水池数量位置容量和补水、天然水源、四类消防系统、内外消火栓、消防泵参数、避险通道和药剂器材 |
| 作战信息卡 | 工艺流程 | 原文流程与涉密或未提供说明 |
| 作战信息卡 | 重点提示 | 原文警示、防护要求、已核对的风险与处置信息 |
| 危险品 | 仓库库存 | 每种存货一条，记录仓库及位置、成分、建筑结构面积、储存形式、单位包装储量、实际总储量、风险和存放条件 |
| 危险品 | 储罐 | 每个储罐一条，记录介质、编号、形式材质、直径高度、设计压力温度、氮封冷冻浮盘保温、容积及实际储量 |
| 组织架构 | 单位联系人 | 每个岗位一条，记录人员、联系方式、岗位职责及上级；兼任岗位分别保留 |
| 地图、应急预案 | 原有地图与预案条目 | 保留既有图名、日期版本、区域、适用范围、正文和附件出处 |

## 录入和核对约定

- 在对应页面点击标准类型按钮添加记录，也可继续编辑原有通用条目。类型切换须明确确认，保存时只接受该类型字段；不同模块不能混用类型。
- 名称、地址仍以单位档案为检索和归属依据。基本情况中的原文名称地址用于核对，不自动改写档案，也不自动调整维护消防单位。
- 字段以原文字符串保存。约数、正负号、压力区间、混合长度单位、数量单位、“/”及涉密说明不得擅自改写；空白代表未提供，不能推定为0、无或否。
- 储罐容积是设计资料，不是实际库存。包装储量不是总储量，不进行单位换算或相乘推算。表格合并单元格的继承关系须人工核对。
- AI按标准类型生成候选记录，所有非空值继续逐字段校验本页原文证据；人工可纠正类型、分类和字段。未经核对不写入草稿，更不会自动发布。同名不同编号储罐不作为同一记录互相覆盖。
- 所有标准记录沿用附件出处、草稿修订号、人工确认共享、不可变发布版本和历史警情引用规则。

## 实现与兼容

`backend/admin/key-site-schema.json` 为字段及类型唯一来源。后端通过已鉴权 `/api/admin/key-sites/limits` 返回标准定义，管理网页据此生成表单和填写指南，AI按同一标准摘录。

结构继续存放在现有草稿及发布版本的JSONB中，标准条目新增可选 `kind`。无需新增数据库表、批量回写或迁移历史资料；未带 `kind` 的旧条目保持原结构。旧App仍可读取 `title/body/fields/sources`，新版补充标准类型与中文标签，危险品可按仓库或储罐编号检索。旧客户端可能仅显示新增字段的英文键，正式App发布仍由用户另行决定。

App标签由 `node scripts/generate-key-site-schema.mjs` 生成；`--check` 及后端测试阻止字段漂移。此命令只生成通用标签，不包含任何单位数据。

## 验证范围

测试覆盖九类记录、非法类型/跨模块字段、原文字符串及单位、容积与储量分离、逐项AI证据、不同编号储罐、人工采用类型保留、HTTP保存发布及历史快照。管理网页用隔离数据库的合成单位完成实际录入、核对和发布；真实样表仅作为结构来源，未自动上传或发布。
